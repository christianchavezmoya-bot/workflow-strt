Divisions, products & features

Build the product catalog that projects and workflows depend on. All catalog admin lives under Settings, not Admin.

Step 1

Catalog hierarchy

Division→ Product→ Features (linked)→ Workflow
  • Division — top-level business unit (e.g. Strata AI, Strata Protect).
  • Product — equipment type (e.g. AIM-100, HA-Coal); optionally assigned to a division.
  • Feature — reusable parts/components in the global library; linked to one or more products.
  • Workflow Type — category label (Installation, Inspection, Commissioning) used when publishing workflows.
Settings tabs: ?tab=divisions, ?tab=products, ?tab=features, ?tab=workflow-types
Step 2

Create a division

Try it mode: add a division in the mock Settings panel.

  1. Sidebar → Settings → Divisions tab.
  2. Click Add division.
  3. Enter Name (required), optional Description, and Sort Order.
  4. Save — division appears as Active in the table.

Step 3

Create a product

  1. Settings → Products tab (?tab=products).
  2. Click Add product.
  3. Enter Name (e.g. AIM-100 Camera), optional description.
  4. Select a Division or leave as No division.
  5. Save — product appears in the catalog table.

Step 4

Build the feature library

  1. Settings → Features tab.
  2. Click Add feature (or Import from CSV/Excel).
  3. Set Name / Part Number, Type (text, number, component, etc.).
  4. Mark as Inventory item or Non-inventory.
  5. For inventory items, configure capture fields (serial, firmware, IP, etc.).
  6. Optionally link to products at creation time.

Step 5

Link features to products

Try it mode: expand a product row and link a feature.

  1. In Settings → Products, expand a product row.
  2. Section LINKED FEATURES (N) shows current links.
  3. Click Link feature and pick from the global library.
  4. Remove a link via the chip delete control on a linked feature.
  5. Features can also show linked products in the Features tab Products column.

Step 6

Workflow types

  1. Settings → Workflow Types tab.
  2. Click Add type.
  3. Enter Name (Installation, Inspection, Commissioning), Icon, Sort Order.
  4. Types appear in the workflow create/publish dialogs as Workflow Type.

Step 7

How the catalog feeds workflows & projects

  • Projects pick one primary Product name — determines which workflow tab and asset configuration apply.
  • Workflows (/work-instructions?product=…) are scoped per product; linked features drive BOM and capture fields in the builder.
  • Workflow Type from Settings labels each published workflow (Installation vs Inspection).
