Projects & project types

Installation, inspection, and mixed projects — how they connect to customers, sites, products, and field workflows.

Step 1

What a project ties together

Customer + Site+ Product+ Team→ Project→ Assets / Inspections

A project is the container for field work. Two independent axes define behaviour:

  • Project type — Internal vs External (approval workflow).
  • Workflow mode — Installation only, Inspection only, or Both (mixed) (which modules appear on the project detail page).

Routes: list /projects, create /projects/new, detail /projects/:id.

Step 2

Start creating a project

Try it mode: open the create-project form.

  1. Sidebar → Projects.
  2. Click Create project (navigates to /projects/new).
  3. Page title: Create project — subtitle explains identity, scheduling, and installation configuration.
  4. Use Save draft to persist without submitting, or Submit project when ready.

Step 3

Customer & site selection

  1. Customer — dropdown: Select existing customer. Auto-fills Customer ID (read-only).
  2. Site — filtered by customer; format {Customer} - {Site Name}; or (No site).
  3. Also capture Job Number, Purchase Order Number, Office, Project Time Zone.
Step 4

Project type — Internal vs External

TypeBehaviour
InternalSkips approval; work can begin once the project is in progress.
ExternalIncludes Pending Approval state; requires approval before execution.

External projects show an info alert about the approval workflow. When approved, set Approval Decision to Approved or Rejected.

Step 5

Workflow mode — installation, inspection, or mixed

Controls which modules are visible on the project detail page.

ModeUI labelUse when
INSTALLATION_ONLYInstallation onlyNew installs, commissioning, asset creation from workflows.
INSPECTION_ONLYInspection onlyRecurring checks; uses project assets and inspection runs; no installation workspace sections.
MIXEDBoth (mixed)Projects needing both install and inspect capabilities on one site.
Inspection-only projects still need a product (for workflow assignment) but hide installation-specific workspace UI.
Step 6

Product & project team members

  1. Product name — select the primary product from Settings catalog (e.g. HA-Coal Controller). Determines available workflows.
  2. Project Manager — single user responsible for the project.
  3. Project Team Members — multi-select active users. These names appear in workflow User select (project team) steps at run time.

Nominate users who can be selected in workflow team-member steps.

Step 7

Status lifecycle & submit

Typical status values:

Draft In Planning Pending Approval Approved In Progress On Hold Completed Closed

  • Save draft — keep editing without advancing status.
  • Submit project — finalise creation; external projects may enter Pending Approval.
  • After save, optionally Copy assets from an existing project via the clone dialog.
  • Assign workflows to assets from the project detail page (see Workflows guide).
