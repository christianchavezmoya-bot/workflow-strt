Workflows & builder

Author work instructions, configure mandatory photos, team selects, and feature capture — then publish to the field.

Step 1

How workflows connect to the catalog and projects

Product→ Workflow config→ Published workflow→ Asset run
  • Sidebar label: Workflows — route /work-instructions.
  • One product tab per catalog product; workflows are scoped to that product.
  • Workflow Type (from Settings) labels each config — Installation, Inspection, etc.
  • Features linked to the product drive installed-feature quantities and BOM in the builder.
  • Project team members nominated on the project populate User select inputs at run time.
Step 2

Create a new workflow

Try it mode: create a draft workflow for a product.

  1. Open Workflows → select a product tab (e.g. HA-Coal Controller).
  2. Click + New Workflow.
  3. Enter Workflow Name, Workflow Type, Description.
  4. Set Installed Features quantities (0 = not included).
  5. Click Create Draft — status Draft.
  6. Open Builder from the list row to add steps.

Step 5

User select — project team members

  1. On the project form, nominate users under Project Team Members (see Projects guide).
  2. In the builder, add input type User select (project team).
  3. Default labels vary by workflow type: Installed By (install), Inspected By (inspect), or Team Member.
  4. At run time, dropdown lists only nominated team members; falls back to all users if empty.
  5. Set Required/Optional like any other input.

Step 6

Features, quantities & BOM

Three layers connect features to a workflow run:

  1. Catalog — features linked to product in Settings → Products.
  2. Workflow create / Installed Features panel — set quantity per feature (0 = excluded).
  3. Builder tabs — Features (N) and BOM (N) for dependency inclusion per step.

Step 7

Publish and assign to assets

  1. In Builder, click Publish → confirm name, type, and description.
  2. Published workflows are locked and assignable to project assets.
  3. Status changes from Draft to Published.
  4. From project detail, assign the published workflow to an asset; field users run it from the mobile or web runner.
  5. Use Run in builder to preview before publishing.
