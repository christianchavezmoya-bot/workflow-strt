Reference Fields
User Guide

Reference fields create relationships between tables, ensuring data consistency by linking records to a single source of truth. When you need data from one table to appear in another, reference fields keep everything in sync.

What Are Reference Fields?

Reference fields are a special field type that create validated links between tables. Instead of manually typing data that exists elsewhere, users select from a dropdown populated directly from the source table.

Key Benefits:

  • Eliminates typos and inconsistencies
  • Updates propagate automatically
  • Validates that referenced records exist
  • Enables click-to-navigate functionality

When to Use Reference Fields

1

Linking Related Entities

When records in one table need to reference records in another.

Projects → Customers Installations → Sites Issues → Installations
2

Ensuring Data Consistency

When the same data should match across all tables.

Customer names Product lists User assignments
3

Creating Dropdown Lists

When options should come from a controlled source.

Site locations (filtered) Products from catalog Status values

Free-Text Input Needed

Use a text field instead for notes, descriptions, or any unique content.

Data is Unique to Each Record

If the value is different for every record and doesn't exist elsewhere, use text or number fields.

Creating Formulas or Calculations

For computed values, use a formula field type.

How to Create a Reference Field

1

Open Table Configuration

Navigate to any table (Projects, Installations, etc.)

Click the ⚙️ Settings icon in the table header

The Table Configuration dialog opens

2

Create New Field

In the "Create new field" section, configure the following:

Field Configuration 
# Field name - Enter a descriptive name
Field name: "Customer Site", "Product Category", "Assigned To"

# Field type - Select "reference" from dropdown
Field type: "reference"

# Link to - Select the source field
Link to: 
  - field-customer (primary key)
  - field-site-name (primary key)
  - field-job-number (primary key)
  - Any composite key or lookup field

# Action - Choose click behavior
Action:
  - "open referenced record" → Opens full record
  - "filter by reference" → Filters data by selection
  - "navigate to reference" → Goes to related page

Click "Create" to save the field

3

Use the Field

The reference field now appears in your table and:

  • Shows a dropdown of valid options
  • Validates entries against the source
  • Enables the selected action on click

Available Actions

When setting up a reference field, choose what happens when a user clicks a value:

Open Referenced Record

Opens a detail view of the selected record

Best for: Quick access to full information

Filter by Reference

Filters the current view based on selection

Best for: Finding related records

Navigate to Reference

Navigates to the referenced entity's page

Best for: Managing referenced records

Best Practices

DO

1. Use Descriptive Names

Good: "Installation Site Location"
Bad:  "Site", "Field1", "Ref"

2. Link to Primary Keys

Link to fields marked as "primary key" or "composite key" to ensure uniqueness and data integrity.

3. Choose Appropriate Actions

  • • Navigation: For managing related records
  • • Open record: For viewing details
  • • Filter: For finding related data

4. Document Your References

Keep track of which fields reference what. This helps when restructuring or debugging.

DON'T

1. Create Circular References

Bad: Table A → B → C → A
Creates confusion and potential loops

2. Reference Temporary Data

Don't link to fields that change frequently or are marked for deletion.

3. Over-Reference

Not every field needs to be a reference. Use text fields for simple, non-critical data.

Troubleshooting

Cause 1: No data in source table

Solution: Add records to the source table first

Cause 2: Linked to wrong field

Solution: Edit field → Change "Link to" selection

Cause 1: Field type doesn't support linking

Solution: Ensure field type is "reference"

Cause 2: No primary keys available

Solution: Create fields with type "primary key" first

Cause: Action requires additional setup

"navigate to reference" needs a route defined

"open referenced record" needs a detail view

"filter by reference" needs filter configuration

Migration from Existing Fields

If you have existing text fields you want to convert to reference fields:

1

Create New Reference Field

Don't delete the old field yet. Create the new reference field alongside it.

2

Test Thoroughly

  • • Verify dropdown shows correct options
  • • Check that actions work as expected
  • • Ensure data validates properly
3

Migrate Data (if needed)

  • • Map old values to new reference IDs
  • • Update existing records
  • • Verify no data loss
4

Remove Old Field

  • • Once confident, hide the old field
  • • After verification period, delete it
